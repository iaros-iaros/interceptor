Saved sessions

Opening a session replaces what is on screen. Nothing is ever saved automatically.

Capture only these hosts every other host still loads normally in the browser — it just isn't shown here

One host per line. A plain hostname works, and so does a regular expression — app.example.com, .*\.example\.com. Leave it empty to capture every host, which is the default. To capture nothing and let all traffic straight through — what the old Passthrough mode did — use a pattern that matches no host, such as ^$.

A host left out is not blocked — it loads normally in the browser, it is simply not captured, not shown, and never stopped in Intercept. This is not a security boundary.

It is also the main speed control. To show you an HTTPS request, Interceptor has to stand in for the site — answering with a certificate it mints, then opening its own connection onward — which costs two TLS handshakes per connection on a single core. A host you do not name skips all of that. The speed half applies to new connections only; the capture half applies immediately.

Rewrite rules applied automatically to matching traffic — nothing stops for you
Change text in bodies Find something in the request or reply body and put something else there.
Change headers Set a header to a value, or leave the value empty to remove it.
Break things on purpose Make matching requests slow, fail, or die — then use the app and watch how it copes. Affected rows are tagged fault so an injected failure is never mistaken for a real one.

First matching rule wins, top to bottom. Requests you have stopped by hand in Intercept are left alone — you are already in control of those. A delay holds a real connection open, and browsers only open about six per host, so a long delay on a busy path will stall that whole host.
